一个给网络新手用的小工具：**双击就能看本机 IP、实时网速、有没有走代理**。

## 一、怎么运行（新手照着做就行）

### Windows

1. 安装 Python 3.8 或更高版本：<https://www.python.org/downloads/windows/>
   **安装时一定要勾选 `Add Python to PATH`**（在安装界面最下面）。
2. 把整个文件夹放到任意位置（例如桌面）。
3. **双击 `启动-windows.bat`**。
   - 脚本会先自检，缺什么会用中文提示你；
   - 自检通过后自动用 `pythonw` 打开窗口（不会残留黑色命令行窗口）。
4. 想省掉"必须先装 Python"这一步？见下面的「打包成 exe」。

### Linux

```bash
# 1) 安装 python3 和 tkinter（多数发行版已自带 tkinter，没有就按下面装）
sudo apt install python3 python3-tk        # Ubuntu / Debian
sudo dnf install python3 python3-tkinter   # Fedora
sudo pacman -S python tk                   # Arch

# 2) 运行
cd 这个文件夹
./启动-linux.sh
# 或者
python3 run.py
```

> 如果只是自己用，**推荐直接用上一节的 `dist/mjNet`（双击即用）**，
> 不需要装 Python，也就不会遇到下面这些环境问题。

**想要像正常软件一样用（推荐）**：装一次桌面集成，之后在应用菜单里点图标就能启动：

```bash
./install-desktop.sh              # 安装：应用菜单图标 + mjnet 命令
./install-desktop.sh --check      # 先看看会装到哪里（不改动系统）
./install-desktop.sh --uninstall  # 卸载（只删菜单项和命令，不动项目文件）
```

安装过程只写入你自己家目录下的这几个位置，**不需要 sudo，也不碰系统目录**：

| 内容 | 位置 |
| --- | --- |
| 应用菜单项 | `~/.local/share/applications/mjnet.desktop` |
| 启动命令 `mjnet` | `~/.local/bin/mjnet` |
| 图标（48/64/128/256 四种尺寸） | `~/.local/share/icons/hicolor/<尺寸>/apps/mjnet.png` |

安装完：按 `Super` 键搜索 **mjNet**，或终端执行 `mjnet`。
想要开机自动启动，就加参数 `--with-autostart`。

### 命令行参数（排查问题用）

```bash
python3 run.py --check     # 环境自检：逐项检查 IP/网关/DNS/代理/公网IP/延迟
python3 run.py --report    # 不开窗口，直接在终端打印一次网络信息

```

`--check` 是最有用的：如果界面有问题，先把它的输出发出来就能定位。

## 二、界面上的每一项是什么意思

| 项目 | 含义 | 新手怎么理解 |
| --- | --- | --- |
| **实时网速** | 按物理网卡的收发字节数差值实时计算 | 单位 **Mb/s**（兆比特每秒）。运营商说的 100M 宽带，满速下载 ≈ 12.5 MB/s ≈ 100 Mb/s。注意 **Mb/s 和 MB/s 差 8 倍**，别被数字吓到 |
| **网络延迟** | TCP 握手耗时（毫秒） | 越小越流畅。<60ms 很好，60~150ms 一般，>150ms 会感觉卡。同时显示**抖动**（延迟波动）和**丢包率** |
| **本机 IP** | 局域网内你的地址，一般是 `192.168.x.x` / `10.x.x.x` | 路由器分给你的"门牌号"，只在局域网内有效 |
| **公网 IP** | 外网看到的出口地址，附国家/地区/运营商 | 上网"对外"的身份。若显示的是机房/海外地址，说明流量走了代理 |
| **网络连接方式** | 有线还是 WiFi、WiFi 名称、信号强度 | 信号 <50% 建议靠近路由器 |
| **代理状态** | 是否走了代理以及走的是哪一种 | 见下方详细说明 |
| **DNS 服务器** | 负责把网址翻译成 IP 的服务器 | 打不开网页但 QQ 能用，通常是 DNS 问题。会自动跳过 `127.0.0.53` 这类本地代理存根 |
| **默认网关** | 你的路由器地址 | 网络不通时，先 `ping` 这个地址判断是路由器问题还是外网问题 |
| **TCP 连接数** | 当前 TCP 连接总数 | 突然暴涨可能是有程序在大量联网 |
| **累计流量** | 程序启动以来的收发总量 | 不是全系统流量，仅供粗略参考 |

### 「代理状态」是怎么判断的

按下面的顺序检查，**先命中先返回**：

1. **环境变量**：`http_proxy` / `https_proxy` / `all_proxy`（Linux 上 curl、git、pip 真正认的是这个）
2. **系统代理**：
   - Windows：注册表 `Internet Settings` 里的 `ProxyEnable` / `ProxyServer` / `AutoConfigURL(PAC)`
   - Linux：GNOME（`gsettings org.gnome.system.proxy`）、KDE（`kioslaverc`）
3. **本机代理端口**：扫描 Clash(7890/7897)、V2Ray(10808/10809)、通用 SOCKS5(1080) 等常见端口

界面上的代理状态分三种，含义完全不同：

| 卡片显示 | 含义 |
| --- | --- |
| **已启用 · 环境变量 / 系统代理** | 明确配置了代理，流量基本确定走代理 |
| **代理程序在运行**（黄色） | 只是探测到代理内核还在后台跑，但**没有配置**系统代理/环境变量。除了 TUN/透明模式，流量其实是直连的 |
| **未检测到代理**（灰色） | 环境变量与系统代理都为空，也没扫到代理端口 |

> 这一点很容易误会：在图形界面里关掉"系统代理"开关后，代理内核往往**还在后台监听端口**。
> 所以关掉开关并不等于"没在用代理"——尤其 Clash 的 TUN 模式会把流量在网卡层接管，
> 压根不需要系统代理设置。**最可靠的判断是看公网出口 IP**（见下面的诊断第 7 层）。

> ⚠️ 重要提醒：**检测到代理端口 ≠ 你正在用代理**。
> 只说明"代理程序正在运行"。如果代理软件开启的是 **TUN / 透明代理模式**，
> 它根本不会去改系统代理设置，但你的流量实际上已经被接管了。
> 所以卡片上会写一句备注说明这一点，判断"是否走代理"最可靠的办法是看
> **公网 IP 的归属地**是否符合预期。

## 三、一键网络诊断（新手最实用的功能）

点底栏的 **🩺 网络诊断**，程序会**由近到远**逐层检查，然后直接告诉你结论，
而不是甩一堆数字给你猜：

```
✓ ① 本机网卡与 IP        [正常]  IP 192.168.1.100，统计到 2 个物理网卡，WiFi 无线 SSID=MyWiFi-5G 信号=94%
✓ ② 路由器（默认网关）    [正常]  192.168.1.1 可达（ICMP，3ms）
✓ ③ 域名解析（DNS）      [正常]  解析 www.baidu.com → 183.2.172.177（10ms）
✓ ④ 国内网络连通         [正常]  可达（阿里 DNS ICMP，17ms）
! ⑤ 国外网络连通         [有异常] 国外服务全部超时
      ↳ 建议：国内正常、国外不通 —— 大多数情况是网络环境所限，通常需要代理才能访问
✓ ⑥ 公网出口与代理       [正常]  出口 IP 203.0.113.45（新加坡）· 已检测到代理（环境变量）

结论：国内上网正常；国外访问不通（常见，通常需要代理）
```

诊断顺序对应「故障定位」的思路，任何一层失败就能直接锁定原因：

| 层 | 检查什么 | 失败意味着 |
| --- | --- | --- |
| ① 本机网卡与 IP | 有没有物理网卡、有没有拿到 IP | 电脑根本没连上网 |
| ② 路由器 | 能不能连上默认网关 | **局域网这一段断了**：查网线/WiFi 密码/重启路由器 |
| ③ DNS 解析 | 域名能否翻译成 IP | **能连路由器但打不开网页**：换 DNS 为 223.5.5.5 |
| ④ 国内连通 | 国内服务能否访问 | **路由器通了但出不了外网**：宽带/光猫/运营商问题 |
| ⑤ 国外连通 | 国外服务能否访问 | 国外不通很常见，**不算故障**，通常需要代理 |
| ⑥ 公网出口与代理 | 出口 IP、归属地、代理状态 | 辅助判断流量是否真的走了代理 |
| ⑦ 流量走向验证 | **绕开代理直连**查一次出口 IP，与当前出口对比 | 两者不同就**百分百证明**流量正在经过代理（这是"关了代理却没变化"的判定依据）|

第 7 层是怎么做到的：新建一个**不带任何 ProxyHandler** 的请求器去查出口 IP（即绕开所有代理设置直连），
再和正常查询的出口 IP 对比。例如：

```
直连出口 198.51.100.7（中国 · 示例省）  ←  你的真实宽带
当前出口 203.0.113.45（新加坡机房） ←  实际出口
两者不同 → 流量确实经过代理
```

> 技术细节：网关和设备探测**优先用 ICMP ping**，如果没有权限或 ping 不可用，
> 会自动退回 **TCP 握手探测**，所以在不允许 ping 的环境里同样能出结果。
> 诊断窗口里的「复制诊断报告」可以把结果贴给别人帮你判断。

### 设计上的几个取舍（为什么这么做）

- **零第三方依赖**：不用 `psutil`/`requests`/`WMI`，Windows 直接 `ctypes` 调
  `GetIfTable2`/`GetAdaptersAddresses`/`GetExtendedTcpTable`，Linux 直接读 `/proc`，
  所以体积小、启动快、不容易因为环境问题跑不起来。装了 `psutil` 会自动当增强用。
- **界面永不卡死**：所有联网请求都丢到后台线程，结果通过队列回到主线程刷新
  （Tkinter 只能在主线程操作控件）。公网 IP 查询 5 秒超时，最慢也不会卡界面。
- **采集频率分层**：网速 1 秒一次（本地读取，几乎无开销）；延迟 2 秒一次（后台线程）；
  公网 IP 60 秒一次；网卡/网关/DNS/WiFi 15 秒一次，代理状态 10 秒一次。
- **公网 IP 多接口容错**：依次尝试 `ip-api.com`（带归属地）→ `ip.3322.net` →
  `api.ipify.org` → `myip.ipip.net` → `ident.me`，任意一个通了就显示，
  全挂了也只提示失败而不是报错崩溃。
- **诊断结论与检查过程分离**：`build_conclusion()` 是纯函数，输入各层状态、输出结论与建议。
  好处是不用真拔网线就能把「网卡坏 / 路由器不通 / DNS 故障 / 外网不通」等场景全部单元测试。
- **桌面集成只动家目录**：`install-desktop.sh` 不写系统目录、不需要 sudo，
  卸载就是删几个文件；图标不用 ImageMagick，而是用 Tk 按目标尺寸重新绘制，保证像素精确。
- **打包成单文件（双击即用）**：用 PyInstaller 把 Python 运行时和程序打在一起。
  打包前会**强制挑选能正常显示中文的解释器**，并在打包后自动试运行一次，
  避免出现"双击没反应"或"界面全是方块"的残次品。
  另外 Ubuntu 自带的 `python3 -m venv` 常因缺 ensurepip 直接失败，而装 python3-venv 要 sudo，
  所以脚本改用 `venv --without-pip` + 下载 `get-pip.py` 引导 pip，**全程不需要管理员权限**。

## 六、常见问题

| 现象 | 原因与解决 |
| --- | --- |
| 双击 bat 闪一下就没了 | 在文件夹里按住 `Shift` + 右键 →「在此处打开 PowerShell」，运行 `python run.py --check` 看具体报错 |
| 提示 `No module named tkinter` | Linux：`sudo apt install python3-tk`；Windows：重装 Python 时勾选 `tcl/tk and IDLE` |
| 网速一直是 0 | 确认下方"统计网卡 N 个"的 N ≥ 1；若为 0，说明网卡被识别成虚拟网卡了，请把这个网卡名字反馈给我 |
| 公网 IP 一直获取失败 | 可能被防火墙/代理拦截了这类请求，试试浏览器能否打开 `http://ip.3322.net/` |
| 延迟里"国外 超时" | 这是**正常现象**：说明到国外（Cloudflare）的直连不通，通常是网络环境所限，不代表故障 |
| Linux 上 WiFi 名称是空的 | 装一个 `nmcli`（NetworkManager）或 `iw`：`sudo apt install network-manager` / `sudo apt install iw` |
| **界面中文显示成方块 □** | 系统缺少 Tk 能用的中文 TrueType 字体。跑 `python3 run.py --check` 会明确告诉你，按提示装字体即可：`sudo apt install fonts-noto-cjk`。程序已经会自动从候选里挑一个**实测能渲染中文**的字体，所以 Windows 和普通桌面 Linux 不会遇到这个问题 |
| 报告里数字看着不对 | 网速只统计**物理网卡**，不含 `lo` 回环、Docker、VPN 隧道等虚拟网卡 |
| 应用菜单里找不到 mjNet | 执行 `./install-desktop.sh` 安装；已装过就按 Super 键搜索，或执行 `update-desktop-database ~/.local/share/applications` 刷新菜单 |
| `mjnet` 命令找不到 | `~/.local/bin` 不在 PATH 中，按安装脚本最后的提示加进 PATH 即可（也可以直接用菜单图标启动） |
| 想彻底删掉桌面集成 | `./install-desktop.sh --uninstall`（项目文件不会被删） |
| 双击 `dist/mjNet` 没反应 | 先确认是 x86_64 架构（`uname -m`）；再在终端运行它，报错会直接显示出来。最常见的是权限丢失：`chmod +x dist/mjNet` |
| 关了代理但显示没变化 | 先跑 `python3 run.py --diagnose`。若第 7 层显示"两者不同"，说明流量**确实还在走代理**：请彻底退出代理程序（不只是关开关）、并清理 shell 里的 `http_proxy`/`https_proxy` 环境变量。卡片上"代理程序在运行"表示内核还在后台跑，此时未配置代理、流量一般是直连的 |
| 想让菜单用免安装版 | `./install-desktop.sh --use-binary`（不用了再跑一次 `./install-desktop.sh` 切回源码版） |

## 八、已知边界

- 网速统计的是**整机物理网卡**的总流量，不是单个程序的流量（按进程统计需要 `psutil` 或驱动级接口，会显著增加复杂度和资源占用）。
- 延迟探测用的是 **TCP 握手**而非 ICMP ping：好处是**不需要管理员权限**（Linux 下 ICMP 需要 root），代价是数值与 `ping` 命令不完全一致。
- "是否走代理"只能从**配置层面**判断，无法 100% 确知流量走向，最终以公网 IP 归属地为准。
- WiFi 信号强度来自系统接口，个别网卡驱动可能不提供，此时显示 0%。
- **中文显示（重要，已彻底查清）**：Tk 8.6 在 Linux 上如果**没有编译 Xft/fontconfig**，
  就完全用不了 TrueType 字体，只能拿 X 服务器里的老式**位图**中文字体（GB2312 字符集），
  界面上就会零散出现方块字。**典型来源就是 conda 自带的 Tk**（实测它的
  `libtk8.6.so` 未链接 `libXft`/`libfontconfig`，而系统自带的 `/usr/bin/python3` 是链接了的）。
  本项目对此有三道防线：
    1. `启动-linux.sh`、`install-desktop.sh`、`build.py` 都会用 `tools/tk_check.py`
       实测解释器的中文渲染能力，**优先选能用的那个**（一般是 `/usr/bin/python3`）；
    2. 程序内部 `has_truetype_fonts()` 会检测当前 Tk 是否有矢量字体，
       并在 `python3 run.py --check` 里直接告诉你换哪个解释器或装哪个字体；
    3. 极少数环境下仍想要指定字体，可在 `~/.config/mjnet/config.ini` 里写：
       ```ini
       [ui]
       font_family = Noto Sans CJK SC
       font_size = 12
       ```
  另外注意：`Font.actual("family")` 在位图环境下会"撒谎"（报回你请求的名字），
  所以判断依据必须是 TrueType 字体探测，而不是它。

## 十、开发过程中真实踩过的坑（留个记录，避免以后重犯）

1. **网速永远是 0**：虚拟网卡识别用了宽泛的子串匹配，WiFi 网卡 `wlo1` 因为含子串
   `lo`（回环）被误判成虚拟网卡而排除。→ 改为「精确名 / 明确前缀 / 明确子串」三级匹配，
   并把这份逻辑抽到 `netparse.py` 让 Windows 和 Linux 共用、可单元测试。
   （教训：像 `lo`、`wg` 这种短关键词**绝不能**用子串匹配。）
2. **代理卡片和报告里没有延迟信息**：`_apply_latency` 只更新了抖动统计器，
   忘了把结果写回 `self.remote.latency`。→ 已修复，且异常不再被静默吞掉。
3. **Linux 上 WiFi 名称读不到**：`nmcli -t` 的输出里 active 字段随系统语言变化
   （中文系统是「是/否」），原来的 `== "yes"` 判断永远不成立。→ 改用语言无关的 `IN-USE` 标记（`*`）。
4. **WiFi 名称显示成了邻居家的网络**：修好上一条后为了图省事改成「取信号最强的一条」，
   结果自家信号不如邻居强，界面显示成别人的 SSID。→ 改为按当前连接的 `BSSID` 精确匹配，
   并保留「标记 → BSSID → 信号最强」三级回退。
5. **界面个别中文变方块（查了很久）**：一开始以为是字体名不对，换成 `song ti` 也没用；
   又怀疑是字号、是字符集覆盖、是渲染缓存。最后逐层排查才定位到**根因**：
   一直在用 conda 的 Python，它的 Tk 没链接 Xft，只能用位图字体。
   换 `/usr/bin/python3` 后界面立刻完全正常（自动用上 Noto Sans CJK）。
   教训：Tk 字体问题要先确认「这个 Tk 到底能不能用 TrueType」，再谈选哪个字体。
   顺带纠正一个错误认知：`Font.actual("family")` 并不能证明字体真的生效。
6. **数值被卡片裁掉（"显示不全，被单元框挡住"）**：把字体调大之后，网速/延迟卡片里
   的数值和说明被卡片下边缘裁掉了。原因是**卡片内容实际需要 154px，而每行只分到 144px**。
   排查时特意量了"内容需要高度 vs 实际分配高度"，而不是凭感觉调；
   修法有四步：① 去掉网速卡片里与 hint 重复的独立说明行；
   ② 图表高度 38→22px、数值字号下调到 20pt；③ 说明文字的换行宽度改为**随卡片宽度自适应**
   （原来写死 360，字体变大后会多折一行）；④ 窗口默认 940×780、最小 900×780。
   最后补了一条**布局回归测试**：逐张卡片断言"需要高度 ≤ 实际高度"，防止再犯。
   代理卡片额外做了截断——代理地址很长，全列出来会折成两三行把卡片撑破。
7. **方块字的次要诱因**：Tk 请求不到中文字体时会被静默回退到位图字体，
   小字号下缺字。→ 字体选择改为实测渲染后再决定。
